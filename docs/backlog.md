### Bundle the Qwen3-ASR Python runtime so qwen3-asr can ship
- **Kind:** missing-capability · **Severity:** med
- **Found:** 2026-10-21, while ungating local ASR models for release
- **Decision needed:** bundle a Python runtime (~size?) in the .app, or port qwen to a native runtime?
- **Context:** `qwen3-asr` is currently hidden in release builds (gated to `debug_assertions` + macOS arm64 in `/Users/denisduvauchelle/Documents/code/tucky/src-tauri/src/asr/registry.rs` `parse()` and the `Some("qwen3-asr")` arm / `load_qwen` in `src-tauri/src/asr/engine.rs`). `load_qwen` spawns `CARGO_MANIFEST_DIR/target/qwen-runtime/bin/python` (a uv venv created by `scripts/setup-qwen-runtime.sh` from `src-tauri/qwen-worker/requirements.txt`: mlx-audio, mlx, mlx-metal, transformers) running `src-tauri/qwen-worker/worker.py`. That venv is a dev-machine build artifact with an absolute compile-time path and is not in `tauri.conf.json` `bundle.resources`/`externalBin`, so on a user's machine the model would download (~713 MB) and then fail to load. Needed: either (a) ship a relocatable, signed/notarized Python + site-packages (likely several hundred MB; must be codesigned for notarization) and resolve it relative to the app bundle at runtime, or (b) port Qwen3-ASR to a native runtime (e.g. mlx-swift or a Rust/ONNX path) and ship it as a sidecar like `tucky-whisper`. Then drop the `debug_assertions` gate, update the registry test, and extend the release smoke test.
